# ProntoFix на TrueNAS CORE — подробная инструкция

Сервер учёта заказов (пользователи и роли, заказы, фото/видео, документы, журнал, веб-версия) для TrueNAS CORE 13.

> **Главное, что нужно знать до начала**
> 1. В **TrueNAS CORE нет Docker** (это система на FreeBSD). Поэтому `docker-compose` здесь не работает. Сервер ставится в **jail** — лёгкий контейнер FreeBSD. Установщик делает всё сам.
> 2. **TrueNAS CORE и FreeBSD 13 больше не развиваются** (компания перешла на TrueNAS SCALE/Community). Установщик берёт пакеты из репозитория FreeBSD. Если репозиторий для вашей версии уже снят, установка остановится с понятным сообщением — тогда используйте **Вариант Б** (Linux-виртуалка с Docker, раздел 12). В долгосрочной перспективе разумно перейти на TrueNAS SCALE.
> 3. Установщик я проверил на синтаксис и логику на Linux. **На настоящем FreeBSD/TrueNAS CORE я его запустить не мог**, поэтому при первой установке возможны мелкие расхождения (имена пунктов меню, версии пакетов). В разделе 13 собраны типичные проблемы. Если что-то пойдёт не так — пришлите мне текст ошибки.

Время: 30–40 минут вашей работы.

## 1. Что понадобится

| Что | Подробности |
|---|---|
| TrueNAS CORE 13.0-U6.x | Любой пул ZFS со свободным местом (фото/видео занимают место: заложите хотя бы 50 ГБ) |
| Постоянный IP для сервера | Например `192.168.1.50`. Выберите свободный адрес вне диапазона DHCP роутера |
| Адрес роутера (шлюз) | Обычно `192.168.1.1` |
| Файл `ProntoFix_TrueNAS_CORE.tar.gz` | Архив, который вы получили |
| Для доступа из интернета | Доменное имя (можно бесплатное динамическое: DuckDNS, No-IP), **белый (публичный) IP** у провайдера и возможность пробросить порты 80 и 443 на роутере |

Далее используются примеры: пул `tank`, адрес jail `192.168.1.50`, шлюз `192.168.1.1`, адрес NAS `192.168.1.10`. Подставьте свои значения.

## 2. Шаг 1. Датасет для данных

Данные (база, фото, видео, документы) лучше хранить в отдельном датасете, а не внутри jail: так их легко делать снимками (snapshots), копировать и переносить.

1. Веб-интерфейс TrueNAS → **Storage → Pools**.
2. Рядом с пулом `tank` нажмите **⋮ (три точки) → Add Dataset**.
3. **Name:** `prontofix_data`. Остальное оставьте по умолчанию (сжатие lz4 — хорошо).
4. Нажмите **Submit**.

Получится путь `/mnt/tank/prontofix_data`.

---

## 3. Шаг 2. Создание jail

1. **Jails → Add** (мастер).
2. **Name:** `prontofix`. **Jail Type:** Default (Clone Jail).
3. **Release:** выберите самый новый из доступных (например, `13.1-RELEASE`). Если список пуст, TrueNAS сам предложит скачать релиз — согласитесь и подождите.
4. **Next → Configure Networking:**
   * снимите «DHCP», заполните **IPv4 Address:** `192.168.1.50/24`;
   * **IPv4 Default Gateway:** `192.168.1.1`;
   * включите **VNET**.
5. **Next → Submit.** Дождитесь окончания создания.
6. Откройте **Jails**, раскройте `prontofix` (стрелка справа) → **Edit → Basic Properties** и убедитесь, что включён **Auto-start** (jail будет запускаться вместе с NAS). Если меняли — **Save**.
7. Включите jail: переключатель **State** (или **Start**).

**То же командами** (Shell на NAS, если удобнее; подставьте свои значения):
```sh
iocage create -n prontofix -r 13.1-RELEASE \
  ip4_addr="vnet0|192.168.1.50/24" defaultrouter=192.168.1.1 vnet=on boot=on
iocage start prontofix
```

---

## 4. Шаг 3. Подключение датасета к jail

1. Остановите jail (**Stop**), если он запущен.
2. **Jails →** раскройте `prontofix` → **⋮ → Mount Points** (или кнопка Mount points) → **Actions → Add**.
3. **Source:** `/mnt/tank/prontofix_data`
   **Destination:** `/var/db/prontofix`
   Если есть галочка «Create Destination», включите её. Если такой галочки нет и при запуске будет ошибка про отсутствующую папку — выполните на NAS (в Shell):
   `mkdir -p /mnt/tank/iocage/jails/prontofix/root/var/db/prontofix`
4. **Submit**, затем снова **Start** jail.

**То же командой:**
```sh
iocage fstab -a prontofix /mnt/tank/prontofix_data /var/db/prontofix nullfs rw 0 0
```

## 5. Шаг 4. Проверка сети в jail

Откройте консоль jail: **Jails → prontofix → Shell** (или на NAS: `iocage console prontofix`) и выполните:

```sh
ping -c 2 192.168.1.1        # шлюз — должен отвечать
ping -c 2 1.1.1.1            # интернет
ping -c 2 pkg.freebsd.org    # DNS и репозиторий пакетов
```

Если **последняя** команда не работает, а предыдущая работает — не настроен DNS. На NAS выполните:
```sh
iocage set resolver="nameserver 192.168.1.1" prontofix
iocage restart prontofix
```
Если не работает даже `ping 192.168.1.1` — проверьте IP/шлюз/VNET в настройках jail и что адрес не занят другим устройством.

## 6. Шаг 5. Загрузка архива в jail

Нужно положить `ProntoFix_TrueNAS_CORE.tar.gz` в папку `/root` внутри jail. На NAS она находится по пути
`/mnt/tank/iocage/jails/prontofix/root/root/`.

**Способ 1 — по SSH/SCP (с компьютера под Windows 10/11, PowerShell):**
1. На NAS: **Services → SSH** → включите службу (Start Automatically — по желанию). В настройках SSH (⚙) временно включите **Log in as Root with Password**.
2. Выполните на компьютере:
```powershell
scp C:\Users\ВАШЕ_ИМЯ\Downloads\ProntoFix_TrueNAS_CORE.tar.gz root@192.168.1.10:/mnt/tank/iocage/jails/prontofix/root/root/
```
3. После установки верните настройки SSH в безопасное состояние (отключите вход root по паролю).

**Способ 2 — через WinSCP:** подключитесь к NAS (протокол SFTP, `root`) и перетащите файл в `/mnt/tank/iocage/jails/prontofix/root/root/`.

**Способ 3 — через общую папку (SMB):** создайте SMB-общий ресурс на `/mnt/tank/prontofix_data/incoming` (**Sharing → Windows Shares (SMB)**), положите архив туда с компьютера. В jail он будет виден как `/var/db/prontofix/incoming/ProntoFix_TrueNAS_CORE.tar.gz`. Дальше в шаге 6 используйте этот путь вместо `/root`.

## 7. Шаг 6. Установка

В консоли jail (`iocage console prontofix`):

```sh
cd /root
tar xzf ProntoFix_TrueNAS_CORE.tar.gz
sh /root/prontofix/truenas/install_in_jail.sh
```

Установщик выполнит 8 шагов: проверит доступ к пакетам, подберёт версию Python, поставит библиотеки (FastAPI, SQLAlchemy и др.), создаст пользователя службы `prontofix`, скопирует программу в `/usr/local/prontofix`, создаст файл настроек со случайными паролем и ключом, установит автозапуск и запустит сервер.

В конце вы увидите рамку примерно такого вида:
```
 ProntoFix УСТАНОВЛЕН И РАБОТАЕТ
 Откройте в браузере:   http://192.168.1.50:8000/app/
 Логин владельца:       owner
 Пароль владельца:      xxxxxxxxxxxxxx
```
**Сразу запишите пароль** (он также лежит в `/usr/local/etc/prontofix.conf`).

Свой пароль владельца можно задать заранее:
`OWNER_PASSWORD=МойПароль123 sh /root/prontofix/truenas/install_in_jail.sh`
(допустимы латинские буквы, цифры и символы `. _ @ % + = -`, не короче 6 знаков).

Установщик можно запускать повторно — он обновит программу, но сохранит настройки и данные.

## 8. Шаг 7. Первый вход и начальная настройка

1. С любого компьютера в вашей сети откройте `http://192.168.1.50:8000/app/` и войдите: `owner` + пароль из шага 6.
2. Убедитесь, что открывается `http://192.168.1.50:8000/docs` (документация API).
3. **Смените пароль владельца на свой** (в jail):
   ```sh
   prontofix-manage reset-password owner
   ```
4. Начальная настройка в приложении (под владельцем):
   * **Направления** → добавьте направления (например, «Стиральные машины», «Холодильники», «Мелкий ремонт»);
   * **Пользователи → Добавить пользователя** → создайте начальников отделов (роль 2) и исполнителей (роль 3);
   * в **Направления** нажмите на направление → назначьте начальника;
   * заказчики регистрируются сами по кнопке «Регистрация» (роль 4); их работников (роль 5) заводит сам заказчик.
5. Если самостоятельная регистрация не нужна: `ALLOW_REGISTRATION=0` в настройках (раздел 10) — тогда пользователей создаёт только владелец.

## 9. Шаг 8. Доступ из интернета с HTTPS

Без HTTPS мобильное приложение и камера/GPS в браузере из интернета работать не будут (современный Android блокирует обычный http, браузеры не дают камеру и геопозицию на незащищённых сайтах). Самый простой путь — **Caddy** в том же jail: он сам получает и продлевает бесплатный сертификат Let's Encrypt.

**Подготовьте:**
1. Домен (например, `service.example.com`), который указывает на внешний IP вашего роутера. Если IP динамический — используйте динамический DNS (DuckDNS, No-IP) и включите обновление адреса на роутере.
2. На роутере **пробросьте порты `80` и `443` (TCP) на `192.168.1.50`** (IP вашего jail).
3. Убедитесь, что у провайдера не «серый» IP (CGNAT): сравните IP в настройках роутера (WAN) с тем, что показывает сайт «мой IP». Если они разные — проброс портов невозможен; см. альтернативы ниже.

**Включите HTTPS** (в консоли jail):
```sh
sh /root/prontofix/truenas/caddy/enable_https.sh service.example.com you@example.com
```
Скрипт установит Caddy, настроит прокси на сервер, переключит ProntoFix на приём только внутренних подключений и запустит всё. Через минуту откройте `https://service.example.com/app/`.

После этого `http://192.168.1.50:8000` перестанет открываться (сервер слушает только внутри jail) — это нормально и безопаснее. Чтобы вернуть прямой доступ по IP: `sysrc prontofix_host=0.0.0.0 && service prontofix restart`.

**Если публичного IP нет (CGNAT) или нельзя пробросить порты — альтернативы:**
* VPN в домашнюю сеть (WireGuard на роутере) — телефон подключается к VPN и работает по адресу `http://192.168.1.50:8000` (но тогда приложение должно допускать http, см. раздел 15);
* недорогой VPS с обратным прокси (Caddy/nginx), который пересылает трафик к вам по VPN/туннелю;
* Cloudflare Tunnel — возможно, но на FreeBSD требует отдельной настройки, и я не проверял её здесь.

## 10. Настройки сервера

Файл `/usr/local/etc/prontofix.conf` (в jail, права 600). Формат — по одной строке `ИМЯ=значение`, без кавычек и пробелов вокруг `=`. После правок: `service prontofix restart`.

| Параметр | Что делает |
|---|---|
| `OWNER_USERNAME` / `OWNER_PASSWORD` | Владелец создаётся **один раз** при самом первом запуске. Позже пароль меняется командой `prontofix-manage reset-password owner`, а не правкой файла |
| `SECRET_KEY` | Ключ входа и шифрования паспортных данных. **Не меняйте и сохраните**: иначе паспорта не расшифровать, а все пользователи будут разлогинены |
| `ALLOW_REGISTRATION` | `1` — заказчики регистрируются сами; `0` — нет |
| `MAX_UPLOAD_MB` | Максимальный размер одного фото/видео (по умолчанию 200) |
| `TOKEN_DAYS` | Сколько дней действует вход (по умолчанию 30) |
| `MAP_PROVIDER` | `osm` (OpenStreetMap), `google` или `custom` — какую карту получает приложение |
| `GOOGLE_MAPS_KEY` | Ключ Google Map Tiles API (нужен при `MAP_PROVIDER=google`) |
| `CUSTOM_TILE_URL` | Адрес своего сервера карт для `custom`, например `https://tiles.example.com/{z}/{x}/{y}.png` |

**Как включить карты Google:** в консоли Google Cloud (console.cloud.google.com) создайте проект и подключите оплату (есть бесплатная квота, но карта нужна) → включите **Map Tiles API** → создайте **API-ключ** и ограничьте его только этим API → задайте квоты и бюджет с оповещением. Затем в `prontofix.conf`: `MAP_PROVIDER=google`, `GOOGLE_MAPS_KEY=ваш_ключ` → `service prontofix restart`. Без ключа приложение автоматически использует OpenStreetMap.

Настройки службы (адрес/порт): `sysrc prontofix_host=...`, `sysrc prontofix_port=...` → `service prontofix restart`.

## 11. Резервные копии, обновление, управление

### Резервные копии (обязательно настройте)
**1. Снимки ZFS (основной способ).** Данные лежат в датасете `tank/prontofix_data`:
**Tasks → Periodic Snapshot Tasks → Add** → Dataset `tank/prontofix_data`, Recursive, расписание ежедневно, срок хранения 30 дней.
Для защиты от выхода диска из строя настройте **Tasks → Replication Tasks** на другой пул или другой NAS.

**2. Резервная копия «одним файлом»** (база + фото + документы + файл настроек с ключом):
```sh
prontofix-manage backup /var/db/prontofix/backups
```
Автоматически каждую ночь (в jail: `crontab -e`, добавьте строки):
```
30 3 * * * /usr/local/bin/prontofix-manage backup /var/db/prontofix/backups >/dev/null 2>&1
50 3 * * * find /var/db/prontofix/backups -name 'prontofix_*.tar.gz' -mtime +14 -delete
```
Периодически копируйте такие архивы **за пределы NAS** (облако, внешний диск): в них находится ключ шифрования.

### Восстановление
```sh
service prontofix stop
cd /var/db/prontofix
tar xzf /путь/prontofix_ГГГГММДД_ЧЧММСС.tar.gz        # вернёт service.db, media/, docs/, prontofix.conf
cp prontofix.conf /usr/local/etc/prontofix.conf && rm prontofix.conf
chown -R prontofix:prontofix /var/db/prontofix
service prontofix start
```

### Обновление программы
Скачайте новый архив, загрузите его в `/root` jail (как в шаге 5) и:
```sh
cd /root && tar xzf НОВЫЙ_АРХИВ.tar.gz && sh /root/prontofix/truenas/install_in_jail.sh
```
Настройки и данные сохранятся. Перед обновлением сделайте резервную копию.

### Команды управления (в jail)
| Команда | Назначение |
|---|---|
| `service prontofix start \| stop \| restart \| status` | управление службой |
| `tail -f /var/log/prontofix.log` | журнал сервера |
| `prontofix-manage list-users` | список пользователей |
| `prontofix-manage reset-password ЛОГИН` | новый пароль пользователю |
| `prontofix-manage set-role ЛОГИН 1` | выдать роль (например, вернуть доступ владельца) |
| `prontofix-manage activate ЛОГИН` | включить отключённого пользователя |
| `prontofix-manage backup [папка]` | резервная копия |
| `prontofix-manage check` | сводка: пользователи, заказы, размер данных |

Сервер сам перезапускается, если упадёт, и стартует вместе с NAS (при включённом Auto-start у jail).

## 12. Вариант Б: Linux-виртуалка с Docker

Используйте, если в jail не удаётся поставить пакеты (репозиторий FreeBSD 13 недоступен) или вы хотите самый предсказуемый способ.

1. **Загрузите ISO Ubuntu Server 22.04/24.04** на NAS (например, через SMB в датасет `tank/iso`).
2. **Virtual Machines → Add:** Guest Operating System — Linux; Name `prontofix-vm`; 2 ядра; 2048 МБ ОЗУ; Disk — новый zvol 40 ГБ (или больше под фото/видео); Network — ваш сетевой интерфейс (bridge); Installation Media — ISO. Запустите и подключитесь через **VNC**, установите Ubuntu (включите OpenSSH server, задайте IP или зарезервируйте на роутере).
3. Скопируйте архив в виртуалку (`scp ProntoFix_TrueNAS_CORE.tar.gz user@IP:~`) и в ней:
```sh
tar xzf ProntoFix_TrueNAS_CORE.tar.gz
sh prontofix/truenas/vm_docker/install_docker_ubuntu.sh
```
Скрипт поставит Docker, создаст файл `.env` со случайными паролем и ключом и запустит сервер: `http://IP-виртуалки:8000/app/`.
4. Данные лежат в `prontofix/server/data` внутри виртуалки: делайте снимки её zvol (**Storage → Pools → zvol → Create Snapshot** / периодические задачи) и храните копию `.env` отдельно.
5. HTTPS: на виртуалке поставьте Caddy (`sudo apt install caddy`) и в `/etc/caddy/Caddyfile` пропишите:
```
service.example.com {
    request_body {
        max_size 250MB
    }
    reverse_proxy 127.0.0.1:8000
}
```
`sudo systemctl reload caddy` (порты 80/443 пробросьте на IP виртуалки). Служебные команды в этом варианте: `sudo docker compose exec repair-server python manage.py list-users` (из папки `prontofix/server`).

## 13. Если что-то не работает

| Симптом | Что делать |
|---|---|
| `pkg: ... could not be fetched` / «репозиторий недоступен» | Нет сети/DNS в jail → шаг 4. Если сеть есть, а пакетов нет — репозиторий вашей версии FreeBSD мог быть снят: используйте Вариант Б |
| Установщик пишет, что нет пакетов `py3xx-fastapi` / `sqlalchemy20` | То же: репозиторий не содержит нужных пакетов → Вариант Б |
| «не хватает библиотек Python» после установки | Прочитайте сообщения выше; недостающие пакеты можно поставить вручную: `pkg install py311-fastapi py311-uvicorn py311-sqlalchemy20 py311-pyjwt py311-python-multipart py311-cryptography` (подставьте свою версию Python) и запустите установщик снова |
| Служба не запускается | `tail -50 /var/log/prontofix.log`; проверьте, что датасет подключён и доступен: `ls -ld /var/db/prontofix` (владелец должен быть `prontofix`; исправить: `chown -R prontofix:prontofix /var/db/prontofix`) |
| Jail не стартует после добавления Mount Point | Не существует папка назначения → создайте её (шаг 3) |
| `Address already in use` / порт занят | Другая программа занимает порт 8000: смените `sysrc prontofix_port=8001` и `service prontofix restart` |
| Открывается по IP, но не с телефона | Телефон должен быть в той же сети (Wi-Fi) или использовать HTTPS-адрес из интернета |
| Caddy не получает сертификат | Проверьте: домен указывает на ваш внешний IP; порты 80 и 443 проброшены на jail; нет «серого» IP; `service caddy status` |
| «Bad Gateway» (502) | ProntoFix не запущен: `service prontofix status` |
| Не загружаются большие видео | Лимит `MAX_UPLOAD_MB` и `max_size` в Caddyfile; на другом прокси — свой лимит тела запроса |
| Забыли пароль владельца | `prontofix-manage reset-password owner` (в jail) |
| Потерян доступ владельца (роль сменена) | `prontofix-manage set-role owner 1` |
| После переустановки не видны паспорта | Был потерян `SECRET_KEY`. Восстановите `prontofix.conf` из резервной копии |

## 14. Чек-лист безопасности
- [ ] Сменён пароль владельца (`prontofix-manage reset-password owner`).
- [ ] Включён HTTPS, наружу открыты только порты 80 и 443.
- [ ] После загрузки архива отключён вход root по паролю в SSH (или SSH выключен).
- [ ] Настроены снимки ZFS и их копия на другой пул/NAS; копия `prontofix.conf` хранится отдельно.
- [ ] Ключ Google (если используется) ограничен API Map Tiles и имеет бюджет с оповещением.
- [ ] Включено шифрование датасета `prontofix_data` в TrueNAS (при создании датасета) — паспортные данные и документы лежат на диске.
- [ ] Получено согласие пользователей на обработку персональных данных (в приложении оно обязательно) и соблюдаются местные требования к хранению паспортных данных.
- [ ] На роутере нет проброса порта 8000 (только 80/443 на Caddy).

## 15. Подключение мобильного приложения

В окне входа приложения укажите адрес сервера: `https://service.example.com` (без `/app/` на конце).
Android 9 и новее блокирует обычный `http://`, поэтому для приложения нужен HTTPS (раздел 9). Для проверок по домашней сети без HTTPS на этапе сборки APK потребуется отдельно разрешить `http` — напишите мне, я добавлю этот режим в тестовую сборку.

Веб-версия: `https://service.example.com/app/` — открывается в любом браузере, на телефоне её можно использовать как запасной вариант.
