# ProntoFix на TrueNAS 27.0.0-RC.1 — подробная инструкция

TrueNAS 27 — это Linux-система (линия SCALE). Сервер ProntoFix работает как **собственное приложение в Docker**: вы вставляете готовый YAML в раздел Apps, система сама собирает образ и запускает контейнер. Никаких jail и FreeBSD-команд (они нужны только для TrueNAS CORE).

> **Важно про RC.1**
> * 27.0.0-RC.1 — **предварительная (тестовая) сборка**: разработчики сами пишут, что ранние версии нельзя использовать для критичных задач. Стабильный релиз 27.0 запланирован на начало декабря 2026.
> * Не храните на этой системе единственные копии важных данных. Заранее скачайте конфигурацию системы (**System → General → Manage Configuration → Download File**) и настройте копии данных.
> * Общее правило для всех релиз-кандидатов: **не обновляйте функции пула (Upgrade Pool)**, пока не уверены, что не будете возвращаться на предыдущую версию — после обновления пула откат может быть невозможен.
> * Мой пакет я проверял на обычном Linux. **Именно на TrueNAS 27 RC.1 я его не запускал**: названия пунктов меню в RC могут слегка отличаться от описанных здесь.

Время: 30–40 минут (плюс 3–10 минут на первую сборку образа).

## 1. Что понадобится

| Что | Подробности |
|---|---|
| TrueNAS 27.0.0-RC.1 | Пул ZFS со свободным местом (фото и видео занимают место, заложите от 50 ГБ) |
| Интернет на NAS | При первом запуске NAS скачает образ Python и библиотеки |
| Пакет `ProntoFix_TrueNAS_27.zip` | Распакуйте на компьютере: внутри папка `src` (там `server` и `web`), два YAML-файла и образец `Caddyfile` |
| Постоянный IP у NAS | Например `192.168.1.10` (зарезервируйте на роутере) |
| Для HTTPS из интернета | Домен (можно динамический DNS), публичный IP у провайдера, возможность пробросить порты на роутере |

В примерах: пул `tank`, адрес NAS `192.168.1.10`. Подставьте свои значения.

## 2. Шаг 1. Подготовка Apps и датасета

1. Откройте **Apps**. Если система просит выбрать пул для приложений — выберите свой пул (например, `tank`) и подтвердите. Дождитесь, пока Apps перейдёт в состояние «Running/Started».
2. **Datasets** → выберите `tank` → **Add Dataset**.
   * **Name:** `apps` (если такого датасета ещё нет), **Dataset Preset:** `Apps` (если пункт есть) → **Save**.
3. Выберите `tank/apps` → **Add Dataset**.
   * **Name:** `prontofix` → **Save**.

Получится путь `/mnt/tank/apps/prontofix`. Здесь будут лежать программа, данные, снимки (snapshots) и резервные копии.

> Для паспортных данных и документов рекомендую включить шифрование датасета (в окне создания датасета → Encryption). Ключ шифрования нужно сохранить отдельно.

## 3. Шаг 2. Копирование файлов на NAS

На NAS нужно поместить папку `src` в `/mnt/tank/apps/prontofix/src` и создать пустую папку `data`.

**Способ 1 — SSH/SCP (рекомендую):**
1. На NAS: **System → Services → SSH** → запустите службу (включите автозапуск при желании).
2. Убедитесь, что у вашего администратора (по умолчанию `truenas_admin`) разрешён вход по паролю (**Credentials → Local Users → пользователь → Edit → Allow SSH login with password**, или используйте SSH-ключ).
3. На компьютере (Windows 10/11, PowerShell), находясь в папке с распакованным пакетом:
```powershell
scp -r .\src truenas_admin@192.168.1.10:~/
```
4. Подключитесь к NAS по SSH (`ssh truenas_admin@192.168.1.10`) или откройте **System → Shell** и выполните:
```sh
sudo mkdir -p /mnt/tank/apps/prontofix/data
sudo cp -r ~/src /mnt/tank/apps/prontofix/src
sudo rm -rf ~/src
ls /mnt/tank/apps/prontofix/src
```
Должно показать `server` и `web`.

**Способ 2 — через сетевую папку (SMB):** создайте SMB-ресурс на `/mnt/tank/apps/prontofix` (**Shares → Windows (SMB) Shares → Add**), выдайте нужному локальному пользователю права записи (**Edit Filesystem ACL**), скопируйте с компьютера папку `src` и создайте папку `data`.

## 4. Шаг 3. Настройка YAML

Откройте `docker-compose.scale.yml` в любом текстовом редакторе (Блокнот подойдёт). Замените:

| Что заменить | На что |
|---|---|
| `tank` (в четырёх путях) | имя вашего пула |
| `CHANGE_ME_PASSWORD` | ваш пароль владельца (латиница и цифры, от 6 знаков) |
| `CHANGE_ME_64_RANDOM_CHARS` | длинная случайная строка |
| `Europe/Kyiv` | ваш часовой пояс (по желанию) |
| `30800` | другой порт, если этот занят (по желанию) |

Случайную строку для `SECRET_KEY` можно получить в Shell NAS: `openssl rand -hex 32` (выдаст 64 символа). **Сохраните её в надёжном месте.** Это ключ шифрования паспортных данных: если потерять, паспорта не расшифровать, а менять его после запуска нельзя.

## 5. Шаг 4. Установка приложения

1. **Apps → Discover Apps**.
2. Рядом с кнопкой **Custom App** нажмите **⋮ (три точки)** → **Install via YAML**.
3. **Name:** `prontofix` (строчные латинские буквы, цифры, дефисы).
4. В поле **Custom Config** вставьте содержимое вашего `docker-compose.scale.yml`.
5. **Save**.

Первый запуск занимает 3–10 минут: NAS скачивает образ Python и собирает приложение. В списке **Installed** приложение будет в состоянии *Deploying*, затем *Running*. Если долго *Deploying* — нормально, подождите; ход можно смотреть в логах приложения (кнопка Logs/«Просмотр логов» у приложения).

---

## 6. Шаг 5. Проверка и первый вход

1. Откройте в браузере `http://192.168.1.10:30800/app/` — должна появиться страница входа Home Master.
2. Логин `owner`, пароль — из YAML (`OWNER_PASSWORD`).
3. Документация API: `http://192.168.1.10:30800/docs`.
4. Первичная настройка (под владельцем):
   * **Направления** → добавьте направления («Стиральные машины», «Холодильники», «Мелкий ремонт»);
   * **Пользователи → Добавить пользователя** → создайте начальников отделов (роль 2) и исполнителей (роль 3);
   * **Направления** → нажмите на направление → назначьте начальника;
   * заказчики регистрируются сами («Регистрация», роль 4), их работников (роль 5) создаёт сам заказчик.
5. Рекомендую сразу сменить пароль владельца на свой (команда — раздел 9). Пароль из YAML используется только при первом запуске: когда он уже создан, изменение YAML пароль не меняет.

## 7. Шаг 6. Доступ из интернета с HTTPS

Мобильному приложению, а также камере и геопозиции в браузере из интернета нужен HTTPS. Самое простое — добавить в то же приложение **Caddy**, который сам получает и продлевает бесплатный сертификат Let's Encrypt.

**Подготовка:**
1. Домен (например, `service.example.com`) указывает на внешний IP вашего роутера (для динамического IP — динамический DNS).
2. Нет «серого» IP (CGNAT): внешний IP роутера должен совпадать с тем, что показывает сайт «мой IP». Если не совпадает — проброс портов невозможен, см. альтернативы ниже.
3. Порты 80/443 самого NAS заняты веб-интерфейсом TrueNAS, поэтому Caddy слушает другие порты (`30080` и `30443`), а роутер перенаправляет на них внешние порты. На роутере создайте проброс:
   * внешний **80** → `192.168.1.10:30080`
   * внешний **443** → `192.168.1.10:30443`

**Настройка:**
1. Скопируйте `Caddyfile.sample` на NAS как `/mnt/tank/apps/prontofix/Caddyfile`, заменив домен и e-mail (удобно через `sudo nano` в Shell или SCP с последующим `sudo cp`).
2. Создайте папки: `sudo mkdir -p /mnt/tank/apps/prontofix/caddy_data /mnt/tank/apps/prontofix/caddy_config`
3. Подготовьте `docker-compose.scale-https.yml` так же, как в шаге 3 (те же `tank`, пароль и **тот же SECRET_KEY**, что в первом YAML).
4. **Apps → Installed → prontofix → Edit** (в режиме YAML) → замените содержимое YAML на `docker-compose.scale-https.yml` → **Save**. Подождите перезапуска.
5. Через минуту откройте `https://service.example.com/app/`.

**Если публичного IP нет или нельзя пробросить порты:** варианты — Cloudflare Tunnel (приложение может быть в каталоге Apps, проверьте в **Apps → Discover**; домен должен быть на Cloudflare), VPN в домашнюю сеть (WireGuard на роутере) или небольшой VPS с обратным прокси. Эти пути я не проверял здесь.

## 8. Настройки (карты, регистрация, лимиты)

Параметры находятся в разделе `environment:` вашего YAML. Меняются так: **Apps → Installed → prontofix → Edit** → правка YAML → **Save**.

| Параметр | Что делает |
|---|---|
| `ALLOW_REGISTRATION` | `1` — заказчики регистрируются сами, `0` — только владелец создаёт пользователей |
| `MAX_UPLOAD_MB` | максимальный размер одного фото/видео (по умолчанию 200) |
| `MAP_PROVIDER` | `osm` (OpenStreetMap), `google` или `custom` |
| `GOOGLE_MAPS_KEY` | ключ Google Map Tiles API для `MAP_PROVIDER: google` |
| `CUSTOM_TILE_URL` | свой сервер карт, например `https://tiles.example.com/{z}/{x}/{y}.png` |

**Карты Google:** в консоли Google Cloud (console.cloud.google.com) создайте проект и подключите оплату (есть бесплатная квота) → включите **Map Tiles API** → создайте API-ключ и ограничьте его только этим API → задайте квоты и бюджет с оповещением. Затем впишите ключ в YAML и сохраните. Без ключа приложение автоматически использует OpenStreetMap.

## 9. Резервные копии, служебные команды, обновление

### Резервные копии (обязательно)
1. **Снимки ZFS:** **Data Protection → Periodic Snapshot Tasks → Add** → Dataset `tank/apps/prontofix`, расписание — ежедневно, хранение — 30 дней. Для защиты от поломки диска настройте **Replication Tasks** на другой пул или другой NAS. В снимки попадает и папка `data` (база, фото, документы).
2. **Сохраните копию вашего YAML** (в нём `SECRET_KEY` и пароль) вне NAS, например в менеджере паролей.
3. **Копия одним файлом** (в Shell NAS):
```sh
sudo docker exec $(sudo docker ps -qf name=prontofix-prontofix) python manage.py backup /data/backups
```

### Служебные команды (в Shell NAS)
Название контейнера обычно содержит имя приложения; найти его можно командой `sudo docker ps`. В примерах ниже подставляется автоматически:
```sh
C=$(sudo docker ps -qf name=prontofix-prontofix)
sudo docker exec -it $C python manage.py list-users
sudo docker exec -it $C python manage.py reset-password owner      # новый пароль владельца
sudo docker exec -it $C python manage.py set-role owner 1          # вернуть роль владельца
sudo docker exec -it $C python manage.py activate ЛОГИН            # включить отключённого пользователя
sudo docker exec -it $C python manage.py check                     # сводка
```
Если контейнеров несколько и команда ничего не находит, выведите список `sudo docker ps` и подставьте ID нужного вручную.

### Восстановление
Остановите приложение (**Apps → Installed → prontofix → Stop**), восстановите папку `/mnt/tank/apps/prontofix/data` из снимка ZFS (или распакуйте в неё архив резервной копии), запустите приложение.

### Обновление программы
1. Сделайте снимок датасета и резервную копию.
2. Замените папку `/mnt/tank/apps/prontofix/src` новой версией (`server` и `web`) — как в шаге 2.
3. В YAML увеличьте номер образа: `image: prontofix:1` → `image: prontofix:2` и сохраните (**Apps → Installed → prontofix → Edit**). Новый номер заставляет собрать образ заново. Данные и настройки сохраняются.

## 10. Запасной вариант: собрать образ вручную

Используйте, если сборка при установке по YAML завершается ошибкой (например, `build` не поддерживается вашей сборкой).

1. В Shell NAS:
```sh
cd /mnt/tank/apps/prontofix/src
sudo docker build -f server/Dockerfile -t prontofix:1 .
```
2. В YAML удалите блок `build:` (три строки: `build:`, `context:`, `dockerfile:`), оставив `image: prontofix:1`. Остальное без изменений. Установите/сохраните приложение, как в шаге 4.

## 11. Если что-то не работает

| Симптом | Что делать |
|---|---|
| Приложение долго в *Deploying*, потом ошибка | Откройте логи приложения. Частые причины: нет интернета/DNS на NAS (**Network → Global Configuration**: DNS, шлюз), лимит скачивания Docker Hub, `build` не принят — тогда раздел 10 |
| «Apps не запускается» / нет пула | В **Apps** выберите пул для приложений (раздел 2). После обновления с 26-BETA известна проблема, из-за которой настройки Docker для Apps не применялись при перезагрузке; в RC.1 она исправлена — если встретили, проверьте версию и выбор пула |
| Ошибка YAML | Проверьте отступы (только пробелы, без табуляции) и что значения `CHANGE_ME_...` заменены |
| `Permission denied` в логах про `/data` | Проверьте, что папка `data` существует и принадлежит root/доступна для записи: `ls -ld /mnt/tank/apps/prontofix/data`. Если датасет создан с ограничивающим ACL — выберите для него пресет `Apps` или временно выдайте права: `sudo chmod 777 /mnt/tank/apps/prontofix/data` и проверьте |
| Порт занят | Измените `30800` в YAML на другой свободный |
| Открывается на компьютере, но не на телефоне | Телефон должен быть в той же сети (Wi-Fi) либо использовать HTTPS-адрес |
| Сертификат HTTPS не выдаётся | Проверьте домен → внешний IP роутера, проброс 80→30080 и 443→30443, отсутствие «серого» IP; логи контейнера `caddy` |
| 502 Bad Gateway | Контейнер `prontofix` не запущен — логи приложения |
| Не загружаются большие видео | Лимиты `MAX_UPLOAD_MB` и `max_size` в Caddyfile |
| Забыли пароль владельца | `reset-password owner` (раздел 9) |
| Паспорта не расшифровываются после переустановки | Изменён или утерян `SECRET_KEY`. Верните прежний из сохранённой копии YAML |
| Нестабильное поведение системы | Это тестовая RC-сборка. Сообщите о проблеме на форуме TrueNAS или вернитесь на стабильный выпуск |

## 12. Подключение мобильного приложения

В окне входа приложения укажите адрес сервера: `https://service.example.com` (без `/app/` и без порта).
Android 9 и новее блокирует обычный `http://`, поэтому для приложения нужен HTTPS (раздел 7). Веб-версия доступна по `https://service.example.com/app/` и работает в любом браузере, в том числе на телефоне.

### Чек-лист безопасности
- [ ] Заменены пароль владельца и `SECRET_KEY`, копия YAML хранится вне NAS.
- [ ] Включён HTTPS; наружу открыты только порты 80 и 443 (на роутере — на 30080/30443).
- [ ] Настроены снимки ZFS и копия на другой пул/NAS.
- [ ] Датасет зашифрован (при работе с паспортными данными), ключ сохранён отдельно.
- [ ] Ключ Google (если используется) ограничен API Map Tiles и имеет бюджет.
- [ ] Получено согласие пользователей на обработку персональных данных (в приложении оно обязательно); соблюдены местные требования к хранению паспортных данных.
- [ ] SSH отключён, если не нужен.
